# WordPress固有チェック

WordPressプロジェクトだと判断した場合(`wp-config.php`, `wp-content/`, `wp-includes/`の存在で判定)にのみ、この項目を確認する。それ以外のスタックでは該当なしとしてスキップしてよい。

## セキュリティプラグイン

**確認すること**: セキュリティ系プラグインが導入・有効化されているか。

**探し方**:
- `wp-cli`が使えるなら `wp plugin list --status=active` が最も確実(実際に有効化されているものだけが分かる)。
- `wp-cli`が無い場合は `wp-content/plugins/` 配下のディレクトリ名を確認する。代表的なもの: `wordfence`, `siteguard`, `all-in-one-wp-security-and-firewall`, `better-wp-security`(iThemes/SolidSecurity), `sucuri-scanner`, `wp-security-audit-log`。ただしディレクトリが存在するだけでは有効化されているか分からない点に注意し、可能なら`wp-content/plugins/<name>/`が最近更新されているか、`.maintenance`ファイルの有無なども補助的に見る。有効化の最終確認は「管理画面で確認してください」と添えてよい。
- 見つからない場合は、最低限プラグインなしでも設定できる項目(ログイン試行回数制限、管理画面URLの変更、REST API/XML-RPCの制限など)がされているかも合わせて確認する。

## 自動アップデート設定

**確認すること**: コア/プラグインの自動バックグラウンド更新設定が意図した状態になっているか(特にメジャーアップデートは公開直後に自動適用されると予期せぬ不具合の原因になるため、無効化を推奨するケースが多い)。

**探し方**: `wp-config.php`の`WP_AUTO_UPDATE_CORE`定数、または`wp-cli`が使えるなら`wp option get auto_update_core.major`などで確認する。コードから追えない場合は「管理画面(更新)またはプラグイン管理画面で確認してください」と報告する。

## 検索エンジンによるインデックスを許可しているか

**確認すること**: 「検索エンジンがサイトをインデックスしないようにする」オプション(`blog_public`オプション)がオフになっているか(オンのままだと本番公開後も検索エンジンにインデックスされない)。

**探し方**: `wp-cli`があれば `wp option get blog_public`(`1`なら許可、`0`ならブロック中)。無ければ管理画面の「設定 > 表示設定」を確認するよう案内する。

## .htaccess(Apache環境の場合)

**確認すること**: 基本的なセキュリティ強化設定が入っているか。

**探し方**: サーバールートまたはWordPressルートの`.htaccess`を開き、以下があるか確認する(全部揃っていなくても即NGにはせず、無いものを列挙して報告する):

- `wp-config.php`への直接アクセスを拒否する記述(`<Files wp-config.php> ... deny from all </Files>` 相当)
- ディレクトリリスティングの無効化(`Options -Indexes`)
- `xmlrpc.php`への外部アクセス制限(使っていない場合)。使っている場合(Jetpackなど)は制限しないよう案内する
- `wp-content/uploads/`配下でPHPファイルが実行されないようにする設定(アップロードされたファイルを起点にした攻撃対策)
- HTTPS強制のリダイレクト設定(http→httpsのリダイレクトがすでに別項目としてチェック対象になっている場合は重複報告しなくてよい)
- バージョン管理系ファイル(`.git`, `.svn`など)への外部アクセス拒否

Nginx環境の場合は`.htaccess`は存在しないので、代わりにサーバー設定(`nginx.conf`やサイト設定ファイル)がリポジトリに含まれていればそれを確認し、無ければ「Nginx設定はコードから確認できないため、サーバー管理者に確認してください」と報告する。

## バックアッププラグイン(バックアップ手段の有無)

セキュリティとは別カテゴリだが関連が深いため、ここで合わせて確認する。`UpdraftPlus`, `BackWPup`, `All-in-One WP Migration`などのバックアッププラグインが導入されているか、または`wp-cli`の`wp db export`やホスティング側の自動バックアップ機能が利用可能かを確認する。導入の有無は確認できても「直近でバックアップが実際に取得されたか」はコードからは分からないため、その旨を明記した上で人による確認を促す(SKILL.mdの「バックアップ」項目を参照)。
